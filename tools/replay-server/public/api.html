Leaderboard API

The website and future in-game browser can use these same JSON endpoints. No login is required. Existing ghost recording, selection, and admin APIs are unchanged.

Choose a source

Every data endpoint accepts source=speedrun (default) or source=ghosts. The current game is game=jak3. Player and mission IDs belong to their source: never join accounts by display name.

Endpoints

  • GET /api/v1/leaderboards/points — ranked point totals, mission counts, tied and untied WR counts.
  • GET /api/v1/missions — mission IDs, labels, groups, player counts, WR times, and subcategory labels.
  • GET /api/v1/missions/{mission_id}/leaderboard — each player's best run, time, place, points, and source link.
  • GET /api/v1/players/{player_id} — player totals and per-mission results.
  • GET /api/v1/status — cache availability, age/staleness, progress, and next refresh.
  • GET /api/v1/scoring — machine-readable scoring rules.

Pagination and groups

Use offset=0&limit=50; limits are 1–100. Follow next_offset until it is null. group=all|main|orb|side filters missions and point totals. Overall ranks still refer to the full selected group, not the current page.

{
  "api_version": 1, "game": "jak3", "source": "speedrun",
  "group": "all", "scoring_id": "il-points-v1",
  "revision": "opaque-snapshot-version", "updated_at": "ISO-8601 UTC",
  "total_players": 0, "ranked_missions": 0,
  "items": [], "total": 0, "offset": 0, "limit": 50,
  "next_offset": null
}

Times are numeric seconds. Timestamps are ISO 8601. Display names are labels, not keys. Treat IDs and revisions as opaque strings. If revision changes between pages, restart at offset zero to avoid mixing snapshots.

Points

First: 100. Second: 97. Third: 95. For places 4 onward:

max(round(94 - (place - 4) * 94 / max(1, total_runners - 3)), 0)

Rounding matches Python: nearest integer, ties to even. total_runners is the number of distinct players with ranked results across that source before group filtering. Only one fastest run per player per mission counts. Exact unrounded tied times share place and points, with competition ranking (1, 1, 3). Equal point totals share overall rank.

Speedrun.com uses verified single-player Any% results for Jak 3 OpenGOAL Missions and each subcategory's moderator-defined default; variants are listed on mission responses. Ghost results are completed, non-truncated submissions from the ghost database. They are not independently verified, and their player identities are not linked to Speedrun.com.

Cache contract

Public result pages send an ETag. Send If-None-Match on repeat requests; a 304 has no body, so reuse your saved response. Results are fresh for 15 seconds, with a further 30-second stale-while-revalidate allowance. HTML always revalidates; content-hashed assets are immutable. Errors, admin responses, identity requests, and live cache status are no-store.

Speedrun.com is refreshed hourly in one rate-limited background job. A complete successful snapshot is atomically saved as JSON on disk. Failed or partial refreshes keep the previous snapshot, report staleness, and retry with backoff. A cold cache returns 503 with Retry-After: 60. The public Refresh button revalidates this service's cache; it does not force a new upstream crawl.

Ghost rankings are cached from database metadata, never by reparsing replay files on a page request. Submissions, renames, and database deletions invalidate that snapshot; player pings do not. The database remains authoritative: deleting a JSON file alone does not delete its time record.

Errors and compatibility

Errors have {"error":"message"} with HTTP 400, 404, or 503. Respect Retry-After, retain cached data offline, and label stale results in game. New fields may be added to v1; consumers should ignore fields they do not understand. No permissive browser CORS is enabled; native game clients can access these public endpoints directly.
